## 二、恢复 ×3 的依据要点

模型原审驳回理由与机械证据直接矛盾：
- zh-023：rationale 自认「证据直接包含答案点完全相同的语句」却仍 reject；
- multi-012：「数量应相等」是证据原句「左侧变量与右侧序列元素的数量应
  相等」的忠实缩写，模型以省略限定为由苛责；
- mixed-022：答案点为术语表英文释义原文逐字引用，模型因条目双语并存过度
  驳回。

恢复语义 = 进入 v2.1 待验证集（pending verification），并非直接置为
ground truth；后续验证仍须走答案级评测。

## 三、契约聚焦盲审（owner 授权路线执行结果）

密封双向盲态（payload 无 case-id / 诊断痕迹 / 预期暗示），Pro-only 契约，
每案最多 3 重试。结果 gate=`CONTRACT_BLIND_REVIEW_BLOCKED`：

| case | 结果 | 说明 |
|---|---|---|
| zh-040 | **confirmed**（1 次通过） | 契约错误未复现，该案按授权路线走完 |
| en-052 / mixed-030 / mixed-033 | error ×4 attempts | **契约错误完整复现**：模型再次全部支持答案点却输出 reject——被本地严格 schema 验证器拦截（"reject/needs_followup without any disagreement"） |

科学含义：持续性契约错误被独立新鲜盲审**实验性证实为可复现的模型行为**
（同批案例中既有不复现的 zh-040，也有三次全数复现的三案），排除了旧
引擎配置偶发的解释。三案维持 BLOCKED 状态、产物留档
（`contract-focus-review/`），**未对任何 case 数据做改写**（rewritten=false
贯穿全部记录）。

失败路径局限（如实披露）：重试耗尽的响应原始文本未被持久化（base
review_case 只保留最终异常消息与尝试计数）；审计依赖错误消息 + 复现
统计而非原文。如需原文级取证，须扩 base 的失败响应留存（属共享冻结模块
修改，需另行立项）。
