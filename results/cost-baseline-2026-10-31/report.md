# 臂2 成本基线报告（T6 / P2-1）

- 日期：2026-10-31
- 仓库：`main` @ `1066d60`（2026-09-09 切臂2 为产品默认后的首个成本基线）
- 性质：**纯离线分析**。只读 `results/answer-level/` 下已密封评测产物；**未采集真实用户
  trace**；未调用外部 LLM/网络；未读取 `data/` 下的 trace/consent。
- 产物：[`cost.json`](cost.json)（机器可读）、[`analyze_cost.py`](analyze_cost.py)（一次性
  复算脚本）、本报告。
- 一句话结论：臂2 把 150 例评测的生成 token 从 **441,496 抬到 1,180,703（2.674×，+167.4%）**，
  增量的 **99.58% 在 prompt 侧**；每 **+0.01 G1** 修正率的毛成本是 **62,751 token / 150 例块**，
  折合 **418 token/查询**。

## 1. 摘要

1. 三基线总 token：**M2 441,496 → 臂1 578,255 → 臂2 1,180,703**；臂2/M2 = **2.674×**
   （+167.4%），臂2/臂1 = **2.042×**（+104.2%，V3 档位的增量）。
2. 增量 739,207 token 中 **736,071（99.58%）在 prompt 侧**，completion 仅 +3,136（+26.6%）。
   即成本来自上下文扩容（10→25 块、3,000→7,000 预算），不是答案变长。
3. 每例分布：臂2 **p50 7,960 / p90 11,459 / p95 12,494 / max 15,781**；M2 对应
   **3,468 / 5,107 / 5,527 / 9,263**。臂2 的**中位数已超过 M2 的 p95**。
4. G1 修正率 **0.4397 → 0.5575（+0.1178）**，等价 **76.5 → 97.0** 个修正要点（分母 174）。
   毛兑换率：**62,751.02 token / +0.01 G1**（150 例块）＝ **418.34 token / 查询**；
   保守口径（partial 计 0）**61,243.33 / 408.29**；每多修正 **1 个要点 36,058.88 token**。
5. 成本上涨是**弥散性**的：top-10 例只占增量的 **15.69%**，单例增量中位 **4,840 token**；
   因此无法靠"截断少数超长 context 例"显著降本，只能改档位/预算或换检索器。
6. **11 例零 token 快速拒答**是 M2 的可比性陷阱：它们使密封 `*_avg` 的分母变成 139
   （3,176.23），统一 150 分母后是 2,943.31；混用分母会把倍数从 2.674× 压到 2.478×。
   这 11 例在臂2 花掉 **90,591 token**（占增量 12.26%），其余 139 例单独看是 **2.469×（+146.9%）**。
7. 真实使用外推（每 1,000 次查询，eval mix）：**M2 2,943,310 / 臂1 3,855,030 / 臂2 7,871,350**，
   增量 **4,928,040**。judge 侧 v1.1 合计 **186,862 token**（占被判定生成评测的
   6.14%–14.97%），但属评测一次性开销，**不进入单查询成本**。
8. 观察方案落点：p95 预警 15,618 / 复评 18,741；均值预警 8,658 / 复评 9,839；拒答率带
   [0.20, 0.40]；回退走 4 个 env（`RAG_REFUSAL_THRESHOLD=0.03` 等），零代码。

## 8. 11 例零 token 快速拒答的影响

**这 11 例**：`multi-029, multi-030, multi-031, multi-033, zh-021, zh-022, zh-026, zh-034,
zh-035, zh-036, zh-042`（10 可答 + 1 探针 `multi-029`）。它们的 `prompt_tokens` /
`completion_tokens` 在 outcomes 中是 **`null`**，不是 0；密封聚合按 0 处理。答案文本是固定
拒绝消息，`generation_ms` 仅 **33–52 ms**（无 LLM 调用）。

**影响一：均值分母失真。** 密封 M2 `report.json` 的 `*_avg` 实际分母是 **139**（token>0 的
例），所以显示 3,176.23；150 分母应为 **2,943.31**（高估 7.9%）。臂1/臂2 没有零 token 例，
分母是 150。**混用会得到 2.478×，统一 150 分母才是 2.674×**——+167.4% 这个对外数字必须
配 150 分母。

**影响二：约 18–20pp 的增幅来自"免费拒答路径消失"，不是上下文扩容。**

| 口径 | M2 token | 臂2 token | 倍数 | 增幅 |
| --- | ---: | ---: | ---: | ---: |
| 全量 150（统一分母） | 441,496 | 1,180,703 | 2.674× | +167.4% |
| 仅 139 个 M2 有生成的例 | 441,496 | 1,090,112 | 2.469× | +146.9% |
| 11 例按 M2 均值计价（假设） | 473,872.41 | 1,180,703 | 2.492× | +149.2% |
| 混用密封均值（均值口径，非总量） | 3,176.23/例 | 7,871.35/例 | 2.478× | — |

11 例在臂2 实际花掉 **90,591 token**（占臂2 总量 **7.67%**，占增量 **12.26%**），均值
**8,235.55/例**。

**影响三：这 11 例同时是 M2 质量最差的样本。** 其中 10 例是可答例却在 33–52 ms 内被本地
拒答（误拒）；臂2 为它们付费并转成真实回答。**所以这部分增量是"买质量"，不是纯浪费**。
同向证据：误拒率 0.3934 → 0.1393（122 可答例中约 48 → 17 例）。

**影响四：外推时不要用 M2 的 3,176.23。** 它既是 139 分母，又隐含"7.3% 的查询免费"这一
已被臂2 移除的路径。**臂2 的 7,871.35 对生产更稳妥**（每查询都付）。

**报告口径建议**：对外引用 +167.4% 时注明"其中约 18–20pp 来自免费拒答路径消失；纯上下文
扩容约 +146.9%～+149.2%"。回退到 M2 配置后，这部分"便宜"会随误拒率回升一起回来。

## 9. 真实使用外推（每 1,000 次查询）

**假设（逐条引用，缺一不可）**：

1. 查询分布与 v2.1 基准一致：可答 **81.33%**、不可答探针 **18.67%**；
2. 单轮问答，不含多轮会话累积的上下文增长；
3. prompt 模板、检索深度、模型、答案长度维持评测配置（臂2 = 25 块 / 7,000 token 预算）；
4. 不含缓存命中、重试、失败重放；不含 embedding/rerank 侧 token（评测未计量）；
5. 不含 judge/监控开销（§7、§12 单列）。

## 10. 数据缺口与口径风险

| ID | 严重度 | 问题 | 影响 | 处置建议 |
| --- | --- | --- | --- | --- |
| G-1 | 高 | 臂1 未跑 al2 judge，无 G1 | 成本-质量曲线断裂；V1/V3 无法分别归因 | 如需归因，补跑臂1 面 judge（约 7 万 token / 180 calls） |
| G-2 | 高 | M2 的 11 例 token 为 `null`；密封均值分母 139 | 混用分母低估倍数 7.3%；下游 `sum()` 需 null→0 | 读取方统一 null→0 且统一 150 分母；不改密封件 |
| G-3 | 高 | 无 TTFT 字段；`retrieval_ms` 恒为 0 | 无法用密封数据定 TTFT 阈值，只能用 `generation_ms` 代理 | 生产侧记录 `ttft_ms`/`retrieval_ms`；评测侧后续补字段 |
| G-4 | 中 | judge 只有聚合 token，无逐例/逐点计量 | 无法按 case 或 query_type 拆 judge 成本 | judge runner 增加逐次调用 token 记录（不改判据） |
| G-5 | 中 | 只计生成调用；embedding/rerank 未计量（默认 reranker=none） | 若开启远端 embedding/rerank，基线不完整 | 成本表单列 embedding/rerank，或显式声明不计 |
| G-6 | 中 | n=150，p95 由最高 7–8 个样本决定 | 阈值有抽样误差，单日小样本 p95 抖动大 | 用 7 日滚动；样本量按 §12.4 |
| G-7 | 中 | 单轮、固定模板、无缓存/重试 | 外推是量级估计 | 首批真实数据到位后重估，区分 cache_hit/multi_turn |
| G-8 | 低 | 拒答有词表（0.3929/0.25/0.1786）与语义（1.0/0.9286/1.0）两套读数 | 误用词表口径会高估拒答失效 | 统一引用 G2' 语义口径，词表仅作历史 |
| G-9 | 低 | +167.4% 混入"免费拒答路径消失" | 其中约 18–20pp 不是上下文扩容价格 | 对外同时给纯上下文扩容近似值（§8） |

## 12. 观察方案（本报告最后一节）

> 目标：在不重开 P1.1 trace 采集线、不保存任何 query/answer 原文的前提下，用**聚合计数器**
> 观察臂2 的真实成本/延迟/拒答，并在越界时触发复评或回退。本节是**方案**，落地需 owner
> 批准；本轮未采集任何真实数据。

### 12.1 生产侧应记录的最小字段（不含 query/answer 原文）

| # | 字段 | 类型 | 用途 | 备注 |
| ---: | --- | --- | --- | --- |
| 1 | `ts_bucket` | UTC 分钟或日桶 | 聚合窗口 | 不记录精确到秒的时间戳 |
| 2 | `route` | enum `sync` / `stream` | 分路径统计 | 流式与非流式成本不同 |
| 3 | `outcome` | enum `ok` / `error` / `contract_error` | 失败率与重试归因 | — |
| 4 | `tokens_prompt` | int | 成本主项（98.7%） | 来自 provider usage |
| 5 | `tokens_completion` | int | 成本次项 | 同上 |
| 6 | `retrieval_k` | int | 实际检索宽度 | 与 env 档位对齐 |
| 7 | `context_chunks` | int | 实际进入 prompt 的块数 | 区分"预算未用满" |
| 8 | `refusal` | bool | 拒答率分子 | — |
| 9 | `refusal_stage` | enum `pre_llm` / `post_llm` / `none` | 区分免费早退与生成后拒答 | **这是成本解释的关键字段** |
| 10 | `ttft_ms` | int | 首 token 延迟 | 当前产品**未埋点**，需新增 |
| 11 | `total_ms` | int | 端到端延迟 | 与 TTFT 分开看 |
| 12 | `retry_count` | int | 重试放大的成本 | — |
| 13 | `cache_hit` | bool | 缓存对成本的抵扣 | 有缓存时必须记 |
| 14 | `model` | enum | 模型变更识别 | — |
| 15 | `config_fingerprint` | 12 hex | 4 个 env 的 sha256 前 12 位 | 回退/灰度时区分配置 |
| 16 | `language_bucket` | enum `zh` / `en` / `mixed` / `other` | 分语言成本 | 粗粒度，无文本 |

**禁止记录（硬边界）**：query、answer、prompt、completion 原文；chunk_id、文档路径、
引用文本；user_id / session_id（若必须，用**按日轮换盐**的 HMAC 且不可反查）；IP、UA；
精确到秒的时间戳（可选）。

### 12.2 建议阈值（超过即触发复评）

| 指标 | 基线（本报告） | 预警 | 触发复评 | 窗口/条件 |
| --- | ---: | ---: | ---: | --- |
| **p95 token/query** | 12,494 | 15,618（1.25×） | 18,741（1.5×） | 7 日滚动 |
| **平均 token/query** | 7,871.35 | 8,658（1.1×） | 9,839（1.25×） | 7 日滚动 |
| **总体拒答率** | 0.30（派生） | 越出 [0.20, 0.40] | 连续 3 日越界或偏离基线 10pp | 7 日滚动 |
| **平均 TTFT** | 未测（无基线；`generation_ms` 均值 1,769.05 仅作参考） | 1,500 ms | 平均 2,000 ms 或 p95 3,000 ms | 首批真实数据后校准 |
| 误拒率（仅回放） | 0.1393 | — | > 0.20 | 150 例带标签回放 |
| G1（回放） | 0.5575 | — | < 0.55（M5d 门禁线） | 硬回退 < 0.52 |
| G2'（回放） | 1.0 | — | < 0.90 | M5d 门禁线 |

**派生说明**：拒答率 0.30 = （28 个探针正确拒答 + 0.1393×122 ≈ 17 个可答误拒）/150。
它是**评测 mix 下的推算值，不是逐例标签复算**；生产真实不可答占比未知，所以带宽而非点阈值。

**TTFT 特别说明**：密封产物只有 `generation_ms`（端到端生成耗时，均值 1,769.05），**没有
TTFT**；TTFT 是首 token 延迟，量级通常显著小于端到端生成耗时，因此上表的
1,500/2,000/3,000 ms 是**初始政策值**（不是从 1,769.05 推导），必须在首批真实数据后按
"基线中位数 +50%"重新校准，校准前只作报警、不作回退依据。

### 12.3 回退触发条件与回退动作

**触发条件（满足任一，且连续 3 日或单次门禁级）**：

| ID | 条件 | 级别 |
| --- | --- | --- |
| T1 成本 | 7 日滚动平均 token/query > 9,839 | 复评 |
| T2 成本尾部 | 7 日滚动 p95 token/query > 18,741，或单日 > 18,741 且持续 2 日 | 复评 |
| T3 延迟 | 平均 TTFT > 2,000 ms 或 p95 TTFT > 3,000 ms | 复评 |
| T4 拒答 | 总体拒答率 > 0.40（过度拒答）或 < 0.20（欠拒答/漏拒）连续 3 日 | 复评 |

| T6 硬回退 | 回放 G1 < 0.52，或成本超预算上界（月消耗 > 批准的 100%） | **回退** |

**回退动作（只改 env，零代码；M4c 已验证 env-only 回退）**：

- 回退后 24h 内复测三项（token/query、拒答率、TTFT），并在下一次回放确认 G1 回落到
  0.4397 附近属**预期**（回退是成本/延迟决策，不是质量改进）；若 G1 未回落说明另有变量，
  需停止回退叙事并重新归因。

### 12.4 样本量与隐私边界

**样本量**（两样本均值比较，α=0.05 双侧、power=0.80；CV 取臂2 逐例 token 的 0.39）：

| 目标 | 每窗口最小查询数 |
| --- | ---: |
| 检出均值 15% 的漂移 | 107 |
| 检出均值 10% 的漂移 | 239 |
| p95 稳定估计 | ≥ 1,000（n=150 时 p95 由最高 7–8 个样本决定） |

未计日间流量构成漂移（overdispersion），实际样本量应上浮。建议：**≥1,000 查询/周**为最小
观察窗口；低于此量级只看周均值与总量，**不看 p95**。

**隐私边界（沿用 P1.1 结论，不重开采集线）**：

- P1.1 的既定策略是 **Minimal-only、默认 Off、显式 consent、本地 `MNEME_DATA_DIR/traces`、
  30 天保留、单 trace 删除/撤回、禁止 exact replay、Graph 不接入**；决策为
  `NO_TRIGGER_FALLBACK`，`docs/STATUS.md` §6 明确"不重开"。
- 本方案只要求**聚合计数器**：不写 trace 文件、不保存原文、不做跨用户关联，因此**不属于
  重开 trace 线，也不需要新的 consent 流程**；但字段清单与保留期应写入 PRIVACY/README。
- 计数器建议**保留 90 天日聚合**，明细按日聚合后丢弃；不出境、不进入评测产物、不与
  `data/` 的真实 trace 混合。
- 若未来确实需要含原文的 trace（用于复现具体失败），必须回到 P1.1 的 consent/保留/撤回
  流程另立项，**不能用本方案的计数器"顺便"采集**。
