# 查询拆解

复杂问题被拆分为子查询并发检索，然后结果融合为单一综合回答。

## 为什么要拆解？

像"比较 2023 年和 2024 年报告关于可再生能源的发现"这样的问题需要：
1. 找到 2023 年报告的发现
2. 找到 2024 年报告的发现
3. 比较两者

单次检索查询很可能会遗漏其中一份报告或稀释相关性信号。拆解确保每个子问题获得自己专注的检索。

## 工作原理

1. **分析**：LLM 分析原始问题并将其拆分为原子子查询
2. **并发检索**：每个子查询通过 `ThreadPoolExecutor` 并行分派到检索流程
3. **结果融合**：所有子查询的结果按 chunk 去重并评分
4. **上下文组装**：构建单一组合上下文发送给 LLM 生成最终回答

## 性能

- 子查询并发运行，因此总延迟接近最慢的单个查询，而非总和
- Chunk 去重防止同一文档被重复计算
- 动态 Top-K 应用于融合结果集

## 集成

查询拆解自动用于：
- **Standard RAG** 流程（`answer_query`）
- **Graph RAG** 流程（`graph_rag_pipeline`）

没有单独的用户开关；Mneme 根据查询结构判断是否需要拆解。
