## 一、机制侦查：99 个检索缺口到底丢在哪一层

侦查配置：fixed 索引（与 M2 同 `prepare_index` 参数、2947 块）、原 query 单发检索
（**无** rewrite/decompose——局限见 §五）、每通道深度 k=70 与 k=300 两档、拒答阈值 0.03
（M2 运行时 .env 无覆盖，已核验）。

### 1.1 缺口五层分解（99 缺口例，宽面 k=300 口径）

| 丢失层 | 例数 | 机制 |
| --- | ---: | --- |
| 检索拒答早退（max RRF < 0.03，context 空） | **39** | 39 例的 max_rrf ∈ [0.021, 0.030)——阈值 0.03 恰好拦下全部；**0 例低于 0.015**（阈值降到 0.015 即全部放行） |
| 刀口截断（真值 rank ≥ dynamic_top_k 刀口） | **40** | 真值融合 rank 中位 64；刀口值实测 12-66（中位 18；min_k=12 只保证 rank<12 恒入） |
| context 预算截断（rank < 刀口但 ≥ 10） | **7** | compute_context_k 默认只放 10 块 |
| 管道内本应进入仍缺（rank < 刀口且 < 10） | **7** | M2 实际走 rewrite 子查询融合，与重放（原 query）结果不同——重放不可复现 M2 内部构成（§五局限） |
| 零通道（dense/bm25 前 300 均未召回） | **16** | 语义/语言对齐缺口，宽度与选择器均无效 |

注：k=70 窄面下零通道为 46 例（16+29+1 由深度 70→300 找回）；**99 缺口 = 39+40+7+7+16 的分解以宽面为准，窄面丢失的 29 例主要是「通道未召回」层**（深度不足）。

### 1.2 物理上限分析（本设计最重要的发现）

真值块融合排序（宽面 83 例在 fused 内）分布：rank<10=10 例，rank<15=14，rank<25=21，rank<40=27，中位 64。

**在当前选择器（刀口 min 12 + context 10 块）下，真值块进 context 的必要条件是 rank<10** →
即便检索宽度无限、选择器不动：P1 缺口率**下限 ≈ (99−10)/122 = 0.73**，历史实测 0.8115。
要把 P1 压到 ≤0.50（回收 ≥39 例），需要真值 rank<39 的 27/83 例全部进入 **且** 选择器容量 ≥39——
这超出「一次单变量」的边界（需要：融合排序变革 + 选择器容量 4 倍 + 阈值放行，见 §二杠杆表）。

**结论：P1 ≤ 0.50 在本轮无任何单一变量可达成。**预注册判决已锁定（M4 §三不得调整），
本设计按「实测增量 + 如实 FAIL 归档」执行；若 owner 希望修订判据，须按 M4 §7「书面复批豁免」条款
以新文档行使（Q-M4b-5）。

## 三、受控实验设计（推荐：阶梯双臂）

### 3.1 臂结构

| 臂 | 变量 | 说明 |
| --- | --- | --- |
| **臂0（历史基线，不重跑）** | 无 | M2 密封产物（bf19e69，7 天内、同仓库同语料、仅评测仪器差异；检索路径零 diff——已核验） |
| **臂1** | V1：`RAG_REFUSAL_THRESHOLD=0.015` | **环境变量覆盖，零代码改动**（配置契约保留）；先清除 39 例早退机制 |
| **臂2** | V1+V3：臂1 + 选择器容量档位（min_k 12→25、context_k max 10→25） | 代码改动需 TDD 先行（`dynamic_top_k` / `compute_context_k` 参数化） |

**归因**（阶梯差分，每层单变量）：臂1 − 臂0（M2）= V1 增量；臂2 − 臂1 = V3 增量。
两臂同轮运行（同模型、同温度 0.1、同数据集 v2.1），M2 数字仅作历史参照（臂0 不重跑——
同轮重跑需追加 ~44 万 token 且无额外归因信息，Q-M4b-4 确认）。

### 3.2 测量协议（M2 复用 + 观测补齐）

- 生成：`generation_runner` CLI（与 M2 同协议，`al1-containment-v1` 口径，密封产物）；
- **观测补齐（关键，M2 缺失）**：逐臂执行后以 `m4b_retrieval_recon.py` 伴生重放
  （同 query、同臂参数，捕获通道候选面/刀口/预算/拒答判定）→ 臂内归属可回溯；
  执行备注（2026-09-06）：产品 Minimal trace 通道依赖沙箱 consent（无 consent 时
  fail-closed 静默 Off，且 M2 惯例 trace Off、实验窗口零真实 trace 写入），
  故观测经评测侧伴生重放落实——零 trace、零 consent、零产品写入；

  （注：臂1 伴生重放传 `RAG_REFUSAL_THRESHOLD=0.015` 以对齐臂1 拒答判定。）
- judge：只对臂2 机械 miss 要点跑（M3 协议 `al2-judge-v1`，同模型）；
- manifest 记录：温度（M2 未记，M4c 补齐）、env 覆盖（RAG_REFUSAL_THRESHOLD）、spatial/selector 参数。

### 3.3 机械裁决（不改判据）

- P1（按臂2）：≤ 0.50 → `PASS`（按 M4 §七）；否则 `FAIL`（归档病理 + owner 产品重决策）；
- 协变：修正率三口径、拒答正确率/误拒率（臂1 预期大降误拒）、citation v2、token；
- 臂1/臂2 差异以 trace 事件归因（「归因 ≠ 效果证明」约束全文生效）。

## 五、局限与风险（如实披露）

1. **重放 ≠ M2 内部构成**：侦查无 rewrite 规划（LLM 调用），7 例「本应进 context 仍缺」与 5 例「重放拒答但 M2 非空」均为 rewrite 差异的体现——侦查只主张候选面/管道能力，不主张复现 M2 逐例；
2. **阈值 0.015 的安全面**：39 例全部放行后，其余 61 例（min 0.015 边界内的探针）改为生成路径——拒答面板由生成策略接管（语义式拒答可能增多）；M4 协变「≥2 例偏离预警」在此生效；
3. **reranker/V4 未入选**：证据不足或越界（V5 上移为架构改动）；如臂2 后 owner 要求第三变量，另行呈批；
4. **温度噪声**：0.1 低温度生成方差小但非零；对照差以 D（臂2−臂1）为主，噪声量级如实报告。
