# 知识库与文件入库体验完整改善方案

**状态：** 待实施  
**日期：** 2026-08-02  
**依据：** `plans/2026-08-02-knowledge-base-ux-decisions.md`  
**替代范围：** 将原有“新 collection 时在 TUI 选择目录并逐个勾选文件”的主流程，升级为“知识库 + 资料目录同步”。原有单一全局监听目录方案仅保留为兼容迁移参考。

## 1. 目标与边界

### 1.1 产品目标

让本地用户无需理解 collection、文件路径、索引重建或 RAG 模式，也能完成以下任务：

1. 第一次启动时创建第一个知识库并放入资料；
2. 后续启动时快速回到上次使用的知识库，或切换到另一个知识库；
3. 将文件拖入资料目录后自动同步新增、修改和删除；
4. 知道哪些文件已成功入库、哪些失败、失败原因是什么；
5. 在回答中确认当前资料范围并打开引用原文件。

### 1.2 本期范围

- 本地单用户知识库的创建、列表、选择、重命名、删除；
- 每个知识库一个主资料目录，递归同步本地支持格式；
- 首次扫描、启动对账、目录监听、手动同步和失败重试；
- TUI 中的任务状态、文件状态、隐私提示、来源跳转；
- 对既有 Chroma collection、manifest 和全局 `RAG_WATCH_DIR` 的无损迁移。

### 1.3 不在本期范围

- 云盘、网页、Notion、Git 等外部连接器；
- 多用户、权限、共享和网络知识库；
- 删除用户磁盘中的文件；
- Graph RAG 的增量图谱算法优化；
- Web GUI 重写。

## 2. 用户体验设计

### 2.1 首次启动：创建第一个知识库

现有 API / 模型引导完成后，若注册表中没有知识库，进入以下向导：

```text
创建第一个知识库
  名称：我的知识库
  资料来源：
  > 选择已有资料文件夹
    创建 Mneme 专用资料文件夹并打开
    先创建空知识库
  隐私提示：命中的资料片段会发送给当前配置的 LLM 服务以生成回答。
  扫描预览：支持 24 | 跳过 3 | 需注意 1
  [开始同步]
```

规则：

- 默认显示名称依次为“我的知识库”“我的知识库 2”“我的知识库 3”，保证唯一；手动输入实时校验，不允许新建时静默打开或覆盖同名库。
- 本地桌面环境用系统原生文件夹选择器；用户可选择由 Mneme 创建的专用目录并直接在系统文件管理器中打开。
- Docker / 无图形环境保留清晰的目录路径输入，并提示应选择已挂载到容器内的资料目录；不伪造无法访问的宿主机选择器。
- “先创建空知识库”必须可继续进入聊天和资料管理页，不因没有文件退出。
- Standard RAG 为默认值。Graph RAG 不出现在此向导；用户在已有资料后从高级设置启用。

### 2.2 后续启动：继续或切换

```text
继续使用：公司制度（24 个文件 · 2 小时前同步）

其他知识库
1. 产品文档（8 个文件 · 昨天同步）
2. 项目 A（空知识库）
3. + 新建知识库
```

- 有上次打开记录时，默认焦点为“继续使用”；无记录时按最近使用排序。
- 选择某一知识库后，先执行轻量扫描和差异预览，再进入聊天；如无变更则无额外打扰。
- 列表提供名称搜索与按最近使用、文件数、最后成功同步时间的排序。
- 当前知识库名称始终显示在聊天状态栏和 `/status` 输出中。

### 2.3 资料目录与同步

资料目录是知识库的持续来源，不是一次性导入位置：

```text
用户拖入 / 修改 / 移走文件
       ↓
递归扫描或监听事件
       ↓
按路径 + 内容哈希计算差异
       ↓
新增 / 更新 / 删除 / 跳过 / 失败
       ↓
单 worker 原子提交索引和 manifest
       ↓
发布新查询快照，更新任务和文件状态
```

- 同步目录时保留相对路径；默认递归扫描，跳过隐藏目录、临时文件、`.git`、常见依赖目录和不支持格式。
- 监听只是加速器；每次打开知识库、手动点击同步、监听出现异常后都要用完整扫描对账，不能依赖事件绝对可靠。
- 首次和手动同步先显示摘要：新增、修改、删除、未变更、跳过、失败。删除只移除对应索引，绝不删除原文件。
- 修改资料时，以原子“替换该来源的 chunk”方式更新，沿用现有 manifest、内容哈希和回滚机制。
- 对相同内容但路径不同的文件，保留独立来源以保证引用正确，同时在文件页提示“可能重复内容”，由用户决定是否处理。
- 扫描版 PDF 无文本、空文件、超限文件、权限错误和解析错误需显示可理解的原因和重试操作。

### 2.4 一次性导入和资料管理

`/files add <path>` 保留为高级能力，但用户必须选择：

1. **复制到本知识库的资料目录并持续同步**（默认、推荐）；
2. **仅索引原路径一次**（标记为“非同步来源”）。

文件页展示：资料目录、上次同步时间、同步任务、已入库/失败/跳过文件、类型、大小、修改时间、chunk 数和来源模式。支持：

- 打开资料目录；
- 预览同步差异；
- 立即同步；
- 重试失败项；
- 从知识库移除某来源；
- 打开原始文件。

### 2.5 回答中的可理解性和隐私

- 回答顶部或底部明确标记“当前知识库：公司制度”。
- 引用保留已有文件路径、PDF 页码和 chunk 信息，并增加“打开原文件”动作；定位失败时只打开文件，不假装能定位。
- 首次创建和每次变更 LLM endpoint 时，显示简短的资料外发说明和“查看详情”。索引、扫描和本地向量库仍明确标注为本地操作。

## 3. 技术设计

### 3.1 用知识库注册表封装 collection

新增持久化的知识库注册表，例如 `${MNEME_DATA_DIR}/knowledge_bases.json`。用原子写入和 schema version 维护，不能仅依赖 `.env`。

```json
{
  "schema_version": 1,
  "last_opened_id": "kb_7f2d",
  "knowledge_bases": [
    {
      "id": "kb_7f2d",
      "display_name": "公司制度",
      "collection_name": "mneme-kb-7f2d",
      "created_at": "2026-08-02T09:00:00Z",
      "last_opened_at": "2026-08-02T10:00:00Z",
      "primary_source": {
        "id": "root_1",
        "path": "C:/Users/name/Documents/Mneme/公司制度",
        "recursive": true,
        "managed": true,
        "last_successful_sync_at": "2026-08-02T10:02:00Z"
      }
    }
  ]
}
```

设计要求：

- 新知识库使用机器生成、符合 Chroma 命名约束的 `collection_name`；`display_name` 可以为中文且只用于用户界面。
- `display_name` 在注册表中按 Unicode 规范化后唯一；生成名称和手动校验均复用同一规则。
- 现有 collection 不强行重命名。迁移时为每个已有 collection 建立一条 registry 记录，`collection_name` 指向原名，显示名默认由原名生成并去重。
- 删除知识库必须先显示影响范围，要求输入显示名确认；仅删除本地 collection、manifest、BM25 和图缓存，不触碰 source directory。
- 本期每库仅支持一个 `primary_source`；注册表结构保留将来扩展为多来源的空间，但不在 UI 暴露半成品能力。

### 3.2 来源归属与差异同步

当前 `sync_sources()` 将 collection 视为单一 desired-set。为了不把“仅索引原路径一次”的来源在目录同步时误删，需要给来源建立归属。

- 在 chunk metadata 与 manifest source record 增加 `source_binding_id` 和 `source_mode`（`managed_root` / `external_one_shot`）。
- 新增 `SourceBinding` / `SourceScanResult` 数据结构，统一传递根目录、相对路径、来源模式、扫描状态和错误信息。
- 将 `compute_source_diff()` 与 `sync_sources()` 改为按 `source_binding_id` 对账；只有当前资料目录拥有的来源才允许被“目录中已删除”规则移出索引。
- 既有没有归属字段的 manifest 来源在迁移后标记为 `legacy_external`，除非用户明确将其迁入或绑定为资料目录。
- `add_files_to_index()` 和 chunk 加载流程接受来源归属参数，确保增量更新、删除、manifest 重建和 Graph cache 失效都保持同一归属。

### 3.3 扫描器、监听器与任务状态

新增独立扫描器，不能把目录遍历逻辑散落在 TUI：

- `discover_sources(root, recursive=True, ignore_rules=...)` 返回支持文件、跳过项和扫描错误，所有路径经现有 `validate_document_path()`、大小限制和 `MNEME_DOCUMENT_ROOT` 校验。
- 目录遍历默认不跟随符号链接；路径使用 canonical path，避免循环和逃逸根目录。
- `FileWatcher` 改为递归监听，并由一次全量对账修正漏事件、重命名和目录移动。
- watcher 回调只能提交任务，禁止吞掉异常；任务结果写入有界状态历史。
- 在 `IndexQueue.submit()` 基础上提供非阻塞同步 API 和带任务 ID 的状态。查询继续读取最近完成的 immutable snapshot，任务完成后才发布新 snapshot。
- TUI 不从 watcher 线程直接打印内容。由主循环消费任务事件并在安全时机刷新提示；`/status` 和 `/files` 必须始终能看到完整状态。

建议的任务状态：`scanning`、`awaiting_confirmation`、`queued`、`indexing`、`completed`、`completed_with_skips`、`failed`、`cancelled`。每个任务记录开始/结束时间、文件计数、失败明细和可重试路径。

### 3.4 TUI 模块与命令

建议新增或重构：

| 模块 | 职责 |
|---|---|
| `src/knowledge_base.py` | 注册表、名称生成/校验、迁移、知识库生命周期 |
| `src/source_sync.py` | 递归扫描、ignore 规则、差异预览、按来源归属同步 |
| `tui/screens/knowledge_bases.py` | 首次创建、后续选择、列表和管理入口 |
| `tui/platform.py` | 原生文件夹选择器、打开文件夹 / 原文件、容器回退 |
| `tui/dialogs/source_sync.py` | 扫描预览、任务结果、失败重试与隐私提示 |
| `tui/service.py` | 持有当前知识库、异步同步任务、watcher 生命周期与状态聚合 |

命令保持简洁并兼容现有用户：

```text
/knowledge                 列出并切换知识库
/knowledge new             新建知识库
/knowledge rename          重命名当前知识库
/knowledge delete          删除当前知识库（仅本地索引）
/files                     查看当前资料目录和同步摘要
/files sync [--dry-run]    预览或执行同步
/files open                打开资料目录
/files retry               重试失败文件
/files add <path>          一次性导入（复制同步 / 仅索引一次）
/files remove <path>       仅从当前知识库移除来源
```

保留 `/mode`，但文案改为“高级检索模式”；默认 Standard，只有在资料已存在且用户确认后才构建 Graph RAG。

## 4. 实施阶段

### 阶段 A：注册表与兼容迁移

1. 实现知识库注册表、原子读写、名称规范化和唯一默认名生成。
2. 用 Chroma 已有 collections 和现有 manifest 生成 registry 记录；迁移可重复执行且无副作用。
3. 发现旧 `RAG_WATCH_DIR` 时只登记“待用户分配的旧配置”，绝不自动附加到任意知识库。
4. 将 `RagApp.run()` 从直接进入 `render_home()` 改为：API onboarding → registry migration → 首次创建或知识库选择。
5. 为已有 collection 保留原 collection name 和所有现有数据文件。

**完成标准：** 升级后旧 collection 可正常打开、查询和删除；新建名称不重复；没有知识库时可创建空库。

### 阶段 B：资料目录和可预览同步

1. 实现递归扫描、系统目录选择/打开和 Docker 回退。
2. 实现 `SourceBinding` 归属字段及按绑定范围的 diff / sync；迁移旧来源为 `legacy_external`。
3. 首次创建时扫描、展示预览、确认并进行首次同步。
4. 把现有 `render_home()` 的模式和 checkbox 文件选择流程删除或改为新向导入口。
5. 在资料页显示目录、同步摘要、文件状态和安全删除语义。

**完成标准：** 支持文件多层目录首次同步；未变更文件不重复嵌入；删除目录内文件只删除该来源的索引；一次性外部来源不会被目录同步误删。

### 阶段 C：后台同步与可靠反馈

1. 在现有 `IndexQueue` 上实现非阻塞任务、任务状态和有界事件历史。
2. watcher 改为递归监听，事件统一进入同步任务；任何异常进入状态页和重试队列。
3. 每次打开和手动同步执行全量对账；监听仅处理低延迟更新。
4. 聊天请求在同步期间继续使用上次成功的 snapshot，任务成功后再切换。
5. 新增 `/files sync`、`/files retry`、`/files open` 和任务摘要。

**完成标准：** 同步失败对用户可见且可重试；同步时可正常发问；程序重启后可补齐关闭期间的文件变动。

### 阶段 D：信任、质量与效率

1. 在回答和状态栏显示当前知识库；实现安全的打开原文件动作。
2. 在首次同步及 endpoint 改动时显示隐私说明。
3. 检测潜在重复内容、空文件和无文本扫描 PDF，提供非破坏性建议。
4. 知识库列表实现搜索、排序、最近使用和空库提示。
5. 更新中英文 README、TUI 帮助、`.env.example`；废弃 `RAG_WATCH_DIR` 的全局语义并写明迁移方式。

**完成标准：** 用户能看出答案来自哪个知识库、能打开来源、能理解资料为何未入库，且不需阅读代码或手动编辑 `.env` 才能完成主流程。

### 5.3 手动验收脚本

1. 全新数据目录首次启动，完成 API 配置，创建空知识库后进入聊天。
2. 创建第二个知识库，验证自动名称不重名；输入已存在名称时不允许覆盖。
3. 选择含多层目录的资料目录，确认扫描摘要、首次同步和引用路径。
4. 关闭程序后新增、修改、删除文件，再次打开，验证对账结果与索引一致。
5. 在同步大文件时发起查询，验证查询使用旧快照且完成后能检索新资料。
6. 导入一个外部一次性文件后同步资料目录，验证该外部来源不被移除。
7. 让一个文件解析失败，验证任务状态、原因和重试入口可见。
8. 打开旧版本数据目录，验证旧 collection 可查询且旧全局 watch 配置不会错误写入知识库。

## 6. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 迁移误伤现有索引 | 只新增 registry，不改写现有 collection 名；迁移幂等并做测试覆盖。 |
| 目录监听漏事件 | 启动和手动同步始终全量对账；监听只作为增量加速。 |
| 同步误删一次性来源 | 用 `source_binding_id` 严格隔离来源范围。 |
| 终端后台输出打断输入 | watcher 线程不直接打印；由主线程消费任务事件。 |
| Docker 无法访问宿主机路径 | 明确要求 bind mount，并提供无图形路径输入回退。 |
| 大目录耗时或失败难排查 | 扫描预览、任务状态、失败明细、重试和不重复嵌入。 |
| 用户误以为资料永远不出本机 | 首次同步和 endpoint 变更时主动展示资料片段外发说明。 |

## 7. 验收定义

以下全部成立时，本方案完成：

- 新用户不需要输入 collection 名、终端文件路径或理解 RAG 模式，即可创建并使用第一个知识库；
- 老用户能从列表选择已有知识库，且历史索引和资料不丢失；
- 每个知识库有独立资料目录和同步状态，旧全局 watch 目录不再决定当前库内容；
- 资料新增、修改、删除可被可靠同步，失败和跳过对用户可见；

- 回答能标明知识库并打开原始来源；
