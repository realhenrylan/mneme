# 知识库与文件入库体验：已确认的产品决策

**状态：** 已确认，尚未实现  
**日期：** 2026-08-02

## 问题背景

当前 TUI 在新 collection 初始化时要求用户依次输入 collection 名、选择目录、在终端中逐个勾选文件，再开始建库。已有 collection 只能靠手动输入名字复用，用户既不能浏览已有 collection，也不能在启动时清楚地管理资料来源。

产品层面应把底层 collection 呈现为用户可理解的“知识库”，并把文件入库从一次性的文件勾选改为可持续同步的资料目录。

## 已确认的决策

### 1. 区分首次启动与后续启动

**首次安装、首次打开**时，用户没有可选知识库，应进入“创建第一个知识库”引导：

1. 完成模型 / API 配置。
2. 创建第一个知识库。
3. 填写名称（默认名称见下文）。
4. 选择资料来源：
   - 选择一个已有资料文件夹；
   - 创建 Mneme 专用资料文件夹并在系统文件管理器中打开；
   - 先创建空知识库，稍后再添加资料。
5. 对选定目录执行首次扫描和入库。

首次流程不展示“选择已有知识库”的列表，也不要求在 TUI 中逐个勾选文件。

**后续打开**时，先展示知识库选择页，而不是要求用户手动输入 collection 名：

```text
选择知识库：
1. 我的知识库（24 个文件，昨天同步）
2. 公司制度（8 个文件，今天同步）
3. + 新建知识库
```

选择已有项即打开该知识库；选择“新建知识库”才进入创建流程。

### 2. collection 是底层实现，知识库是用户概念

- 一个知识库对应一个底层 collection。
- 用户界面使用“知识库”，不把 collection 名称作为主要概念暴露给普通用户。
- 知识库需要能创建、列出、选择、重命名、删除，并显示当前使用的知识库。
- 每个知识库拥有自己独立的资料目录、同步记录、文件列表和状态；不得用全局 `RAG_WATCH_DIR` 代表所有知识库的资料来源。

### 3. 默认名称必须唯一，且不得静默复用

- 首个默认名称为“我的知识库”。
- 若已存在，依次生成“我的知识库 2”、“我的知识库 3”等未被占用的名称。
- 用户手动输入名称时立刻校验重名。
- 重名时必须明确提示“知识库已存在，请选择已有知识库或换一个名称”；新建操作绝不能静默打开、覆盖或合并到已有 collection。

### 4. 主入库方式改为“绑定资料目录并同步”

- 创建知识库时绑定一个资料目录；该目录是可持续维护的资料来源。
- 用户把支持的文件拖入该目录后，Mneme 自动发现并索引。
- 文件被修改时更新其索引；从目录移除时同步移除其索引。
- 启动知识库时先进行一次递归差异扫描，再启动目录监听，以补齐应用关闭期间的变更。
- 用户可保留“一次性导入外部文件”作为高级入口，但需要明确选择“复制到知识目录并持续同步”或“仅索引本次文件”。

### 5. 用户应看得见同步结果

入库不能静默进行。界面至少展示：

- 新增、修改、删除、未变更、跳过、失败的文件数量；
- 正在处理的进度和当前文件；
- 跳过 / 失败的原因，以及重试入口；
- 上次成功同步时间和当前资料目录；
- 文件级元数据：相对路径、类型、大小、修改时间、解析状态和 chunk 数。

同步在后台串行执行；聊天在同步期间继续使用上一个一致的索引快照，完成后自动切换到新版本。

### 6. 其他已确认的用户体验改进

- 新用户默认使用 Standard RAG；Graph RAG 作为可解释、可选的高级模式，不在创建知识库前要求选择。
- 后续启动优先提供“继续上次使用的知识库”，同时保留切换和新建入口。
- 空知识库是有效状态：用户可以先建库、后放资料，系统不能因为资料目录暂时为空而退出。
- 首次同步前展示扫描预览（支持、跳过、失败的数量和原因）；用户确认的是资料范围，而不是在终端逐个勾选文件。
- “从知识库移除”默认只删除索引，绝不删除用户磁盘中的原始文件；任何磁盘删除能力均不属于默认流程。
- 每个回答明确标识当前知识库，引用应能打开原始文件并尽可能定位到页码或章节。
- 首次建库时明确提示：索引在本地执行，但回答、查询改写或 Graph RAG 处理时，命中的资料片段会发送到用户配置的 LLM 服务。
- 扫描时识别重复内容、无可提取文本的扫描 PDF、空文件等质量问题；仅提示并给出处置建议，不自动删除资料。
- 知识库列表应支持按名称、最近使用、文件数、最后同步时间进行查找和排序。

## 不在本次决策范围内

- 云盘、Notion、网页等外部数据源；
- 多用户权限和知识库共享；
- Graph RAG 的增量图谱构建策略。

这些能力可在本地资料目录同步稳定后再扩展。
