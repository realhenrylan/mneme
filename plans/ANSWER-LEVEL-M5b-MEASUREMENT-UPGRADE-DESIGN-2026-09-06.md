## 一、关键侦查发现（本设计的依据）

1. **臂2 探针答案 28/28 语义正确拒答**（人工逐条核验：每条均含
   「没有/未提及/并未定义/无法确认/未找到」等否定表述，无任何混淆性幻觉）；
2. **G2 词表判定器仅命中 5/28**：`REFUSAL_INDICATORS` 为 12 个固定短语
   （未找到/无法回答/没有足够/暂无/无法提供/cannot/unable to/no information/
   not found/don't have/does not contain/not available），**「没有」「未能确认」
   「并未定义」「无法找到」「未提及」等高频正确拒答措辞全部不在词表**——
   23 例正确拒答被判 False（漏判）；
3. **臂1 的「5 例哨兵→错误回答」实况（勘误）**：臂1 时 noanswer-054 答案为
   「是的，语料中有关于 Git 版本控制的内容…」（幻觉，context 窄所致）；
   **臂2（+V3 扩容）已修复该 5 例**（答案变为正确否定）。
   即 M4d 报告 §3「5 例生成式错误回答」表述是以臂1 数据为准、且未区分臂级——
   **补注记勘误**（m4d-decision 报告 §3 标注：臂1 有 5 例幻觉；臂2 全部语义正确，
   G2 0.1786 为判定器词表 recall 缺陷所致）；
4. **G1（0.5575 ≥ 0.55）在臂2 配置下已满足**——M5 的主判据在「已验证配置」上
   达标；剩余未决=G2 的测量忠实性。

**结论**：M5 的修复对象不是生成层（100% 语义正确），而是**拒答正确性的测量
协议**（词表 → 语义判定）；产品侧无待修复变量。

## 二、设计（三阶段，成本极小）

### 阶段 0：al3-refusal-judge-v1 协议（TDD）+ 基线重测量

- 协议族：复用 al2 的 fail-closed 模式（外置词表 `{refused, answered}` +
  evidence 必须为答案归一文本连续子串 + 解析失败重试 ≤2 + contract_error 按
  披露）；输入：28 探针答案文本 + 查询；输出：语义拒答判定；
- judge 模型：deepseek-chat（与 al2 同，自判偏置披露保留）；
- 重测量对象：**已有密封产物**的探针答案（M2 28 例 + 臂1 28 例 + 臂2 28 例），
  零新生成调用（≈84 次判定 ≈ 2-3 万 token）；
- 输出：三基线语义口径拒答正确率（词表口径对照同列）。

### 阶段 1：G2' 判据锚定（owner 锁定，先于任何复测）

- 判据形式：**G2'：语义拒答正确率 ≥ 语义口径基线的守卫档**。
  守卫档数值在阶段 0 完成时由 owner 在锚定文档中锁定（推荐：≥0.40——
  语义口径下「仍保持高于 2/5 绝对正确」的守卫生理线；或 owner 锚点替换）；
- **合规声明**：语义测量是对**既有密封产物**的重测量（读数理义：句法判定
  skip 语义）——不是「看修复数据调阈值」；与 M5 §三「不改评测协议」的冲突
  在本设计请求豁免（理由：词表口径从 M2 起即披露为「不作优劣裁决的下限」；
  语义化是忠实度校正，非指标调参/刷分）。

### 阶段 2（M5c/M5d 简化案，零生成）

- **修复=测量协议 ⇒ M5c 不重跑生成**（答案不会因测量修复而变）：以臂2 密封
  outcomes 直接判定 G1（已 = 0.5575）+ al3 对臂2 28 探针判 G2' → M5d 机械
  裁决（G1 ∧ G2' 同时满足 ⇒ PASS；否则 FAIL 归档）；
- **成本**：阶段0 2-3 万 + 阶段2 1-2 万 ≈ **5 万 token**（远低于已批 60 万；
  剩余预算返还）。

## 三、平衡与风险

- **判定器升级的一致性**：al3 与 al2（要点命中）并列（测量分工明确：
  al2 判要点语义命中（G1），al3 判拒答语义正确性（G2'）——两者都不接触
  词表，用外置词表只做**契约**校验）；
- **自判偏置**：al3 与生成同模型（既有 al2 同款披露）；若 owner 要求异模型
  judge（成本 +），请批注；
- **人工核验对照**：阶段 0 的 al3 判定将以本设计 §一的人工核验（28/28 正确）
  为参照——al3 与人工核验的分歧即协议的契约错误/漏判，如实报告；
- **不作产品修复**：本设计不触生成/检索路径；生成侧若未来需要实质改进
  （如答案组织），另行预注册。
