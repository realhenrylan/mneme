## 一、锁定参数（不可更改、不可扩大）

| 参数 | 值 | 语义 |
|---|---|---|
| `SAMPLE_TARGET` | `200_real_queries` | 达到即停止采集，进入分析 |
| `COVERAGE_FLOOR` | `cross_document_gte_30` | 跨文档类下限 30 条；sync/stream 按自然分布，不人为配额 |
| `TIME_CAP` | `4_weeks` | 到点即停，无论数量 |
| `PATROL_INTERVAL` | `every_50_traces` | 每满 50 条做一次只读完整性巡检 |
| `RETENTION` | `30_days_local_only` | 数据仅在本地 `MNEME_DATA_DIR/traces`（默认 `~/.mneme/traces`），不上传 |
| `EXACT_REPLAY` | `forbidden` | 不因启用而放开 |
| `PUSH_SAFETY` | `no_trace_data_to_remote` | trace 数据与 `consent.json` 绝不被 stage/commit/push |

停止条件：`SAMPLE_TARGET` / `COVERAGE_FLOOR+SAMPLE_TARGET 组合` / `TIME_CAP`
**三者先到为准**。若 `TIME_CAP` 或 `SAMPLE_TARGET` 先到而跨文档类不足 30 条，
采集期同样结束（不延长），缺口如实记入分析输入，不以继续采集弥补。

## 二、分析问题（只答这三个）

`ANALYSIS_QUESTIONS = dense_bm25_miss | funnel_loss_attribution | stream_vs_sync_gap`

1. **dense_bm25_miss**——dense/BM25 单通道候选完全缺失或严重错位的查询具有
   什么特征？缺失是否集中于特定查询类型？（trace 提供 `retrieve.dense` /
   `retrieve.bm25` 分通道 chunk_id/rank/score）
2. **funnel_loss_attribution**——候选从 dense/BM25 → RRF 融合 → dynamic
   top-k 截断 → selector 同源约束 → context 构建各环节的 case 级损失归因，
   对应 P1.0 诊断的「候选召回 96.2% → final context 保留 61.0%」缺口逐层
   落到真实查询。
3. **stream_vs_sync_gap**——stream 与 sync 在同一 planning profile 下的
   漏斗形态差异（自然分布对照，不做干预）。

分析只读取 trace 匿名元数据（稳定 ID、rank/score、长度/脚本/盐化哈希、
延迟），不重建、也不得尝试重建任何原文。

## 三、预注册触发条件与回退

- `PREREGISTER_TRIGGER = quantifiable_bottleneck`：只有当某个**可量化瓶颈**
  达到预注册阈值、且集中于特定查询类型时，才允许发起下一次受控实验。
  示例锚点（owner 给定）：某通道候选完全缺失率 ≥15% 且集中于特定查询类型。
  判定必须基于 trace 计数统计，不得以个案印象替代；具体阈值在分析启动时
  按本节锚点预先登记，不得看数据后再定。
- `NO_TRIGGER_FALLBACK = archive_and_return_to_product_line`：未达触发条件时，
  trace 就地归档留存（仍受 30 天滚动清理约束），产品线回归正常迭代；
  **不为"用掉已采数据"而设计实验**。

## 四、归因 vs 效果证明分离

`PROMOTION_METRICS = answer_level_on_frozen_v2011`

- **归因靠 trace**：回答"损失发生在哪一层、什么类型的查询上"；
- **效果证明靠冻结评测集**：任何策略改动是否改善质量，只能在冻结的
  v2.0.11 评测资产上做答案级对比验证；
- 两类结论分开书写，**禁止**用 trace 统计量直接宣称质量改进或作为
  promotion 依据。

## 五、采集期纪律

1. **采集期内禁止任何检索策略改动**——dynamic top-k / selector max_per_source
   / 拒答阈值 / reranker / Graph / rewrite-decompose 全部冻结，否则 trace
   分布失去归因基线；
2. 巡检：每满 50 条执行
   `python -m src.production_observability patrol`
   （退出码 0=完整性通过含空库、1=存在篡改/缺 manifest、2=路径非法）；
   巡检只读、无网络、输出不含任何事件内容；
3. 观测功能保持默认 Off；仓库内零真实 trace 数据（运行时守卫 + `.gitignore`
   + README 推送前自检三层防御）;
4. 采集由 owner 手工 `/consent on` 开启、`/consent off` 随时撤回并清除本机
   已封存 trace；单条删除 `/delete-trace <32位ID>`。

- Exact replay（永久 forbidden，除非 owner 另行修订契约 §2.4）。
