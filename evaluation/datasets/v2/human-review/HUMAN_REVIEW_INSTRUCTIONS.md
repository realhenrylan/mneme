# 人工终审填写说明（v2 标注草稿）

> 本包共 150 条，由真人逐条审阅并填写。当前标注为 LLM_ASSISTED 状态，**未经人工批准**；本包是人工终审的输入，**尚未进行人工终审**，不得进入 v2.1。

## 盲态声明

- 本包**不含**自动二审的结论、置信度、理由或审阅模型名；
- 本包**不含**修复动作、任何划分身份、检索分数、候选集或历史评测结果；
- 请仅依据每条中的 query、多轮上下文、草稿标签与 chunk 证据独立判断，不要受包外信息影响。

## 每行如何填写

每行只允许填写以下三个字段，其余字段（case_id / query / 草稿标签 / evidence）**不得改动**：

| 字段 | 填写内容 |
|---|---|
| human_review_decision | 三选一：`confirmed` / `reject` / `needs_followup` |
| human_reviewer | 你的审阅人标识（姓名或工号） |
| human_review_notes | 理由；`reject` 与 `needs_followup` 必须填写 |

## 判定口径

- `confirmed`：问题、答案点、拒答判定和所有证据都正确；
- `reject`：存在事实、证据、来源或拒答错误；
- `needs_followup`：人工无法确定，需要补充来源或证据。

## 核验要点

1. **答案点必须有证据**：每个答案点须由证据中的连续 snippet 直接支持；需要查看完整 chunk 原文时，按 chunk_id 在 `data/v2-corpus/chunks/chunks.jsonl`（source 字段与证据的 source_id 一致）中查证；
2. **拒答行**（should_refuse=true、无证据）：判断该问题在本地语料下是否确实无法回答；
3. **多轮行**：结合 previous_turns 上下文，判断当前问题是否合理衔接、拒答判定是否与对话链一致；
4. **跨文档断言**：跨越多个 source 的答案点，须在各自文档中都有对应证据；
5. **不得放宽标准**：为凑齐 150 条 confirmed 而降低证据标准是不允许的；拿不准就填 `needs_followup`。

## 完成之后

- 150 条全部由真人填写后，才可另行讨论如何导入人工审阅结果；
- 本工具**绝不自动填值**，也不会在无人工确认的情况下写入任何批准标记；
- 未完成 150 条人工填写并确认之前，不得进入 v2.1。
